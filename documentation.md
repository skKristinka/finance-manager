# Техническая документация проекта «Менеджер личных финансов»

## 1. Общая информация о проекте

**Название проекта:** Менеджер личных финансов.

**Тип проекта:** консольное приложение на языке Python.

**Цель проекта:** разработка приложения для учёта личных доходов и расходов, контроля текущего баланса и анализа финансов пользователя.

Проект разрабатывается командой с распределением обязанностей между участниками. Каждый участник отвечает за определённую часть разработки, тестирования, безопасности или документации.

## 2. Назначение и основные функции

Приложение предназначено для ведения личного бюджета. Оно позволяет создавать категории финансовых операций, хранить информацию о доходах и расходах, управлять балансом счёта и формировать отчёты.

В текущей реализации предусмотрены следующие возможности:

- создание категорий доходов и расходов;
- создание финансовых операций с суммой, категорией, датой и описанием;
- добавление операций на счёт;
- изменение баланса при добавлении доходов и расходов;
- пополнение и списание средств;
- расчёт общей суммы доходов и расходов;
- расчёт разницы между доходами и расходами;
- группировка операций по названиям категорий;
- проверка некоторых некорректных данных с помощью исключений `ValueError`.

Пользовательский интерфейс и сохранение данных между запусками требуют дальнейшей реализации.

## 3. Требования к системе

### 3.1. Функциональные требования

Система должна предоставлять следующие возможности:

1. Создавать категории доходов и расходов.
2. Создавать финансовые операции с указанием суммы и категории.
3. Хранить информацию о счёте и связанных с ним операциях.
4. Рассчитывать текущий баланс.
5. Учитывать доходы и расходы при изменении баланса.
6. Формировать отчёты по доходам, расходам и категориям.
7. Проверять корректность вводимых данных.
8. Предоставлять пользователю удобный интерфейс для работы с финансовой информацией.
9. Предусматривать сохранение данных для последующего использования.

Пункты 8 и 9 требуют дальнейшей реализации.

### 3.2. Нефункциональные требования

- **Простота использования:** команды приложения должны быть понятными пользователю.
- **Надёжность:** некорректные данные должны обрабатываться предусмотренным способом.
- **Сопровождаемость:** код разделён на логические модули.
- **Тестируемость:** основные функции должны проверяться автоматическими тестами.
- **Безопасность:** приложение не должно хранить пароли и другие секретные данные в исходном коде.

## 5. Архитектура и основные классы

Исходный код приложения находится в каталоге `src/finance_manager/`.

### 5.1. Category

Класс `Category` описывает категорию финансовой операции.

Основные атрибуты:
- `name` — название категории;
- `type` — тип операции: `income` или `expense`.

Класс проверяет, что название не пустое, а тип соответствует допустимым значениям.

### 5.2. Transaction

Класс `Transaction` описывает отдельную финансовую операцию.

Основные атрибуты:
- `amount` — сумма операции;
- `category` — объект категории;
- `date` — дата и время операции;
- `description` — описание операции.

Сумма должна быть больше нуля, а категория должна быть объектом класса `Category`.

### 5.3. Account

Класс `Account` представляет финансовый счёт.

Основные атрибуты:
- `name` — название счёта;
- `balance` — текущий баланс;
- `transactions` — список операций.

Основные методы:
- `get_balance()` — получение баланса;
- `add_transaction()` — добавление операции и изменение баланса;
- `deposit()` — пополнение счёта;
- `withdraw()` — списание средств с проверкой доступного баланса.

### 5.4. Report

Класс `Report` формирует сводную информацию по операциям счёта.

Основные методы:
- `get_total_income()` — расчёт общей суммы доходов;
- `get_total_expense()` — расчёт общей суммы расходов;
- `get_balance_difference()` — расчёт разницы между доходами и расходами;
- `group_by_category()` — группировка сумм операций по категориям.

Подробная диаграмма классов представлена в файле `docs/UML.md`.

## 7. Участники и распределение обязанностей

Работа над проектом разделена между участниками:

1. **Основная логика:** создание классов и реализация бизнес-логики.
2. **Пользовательский интерфейс:** организация взаимодействия пользователя с приложением.
3. **Безопасность и валидация:** проверка входных данных и обработка ошибок.
4. **Тестирование:** разработка и запуск автоматических тестов.
5. **Техническая документация и DevOps:** организация репозитория GitHub, подготовка README, UML-диаграммы, технической документации и презентации.

## 8. Командная работа и контроль версий

Для совместной разработки используется GitHub.

- Каждый участник работает в отдельной ветке.
- Изменения предлагаются через Pull Request.
- Перед объединением изменений необходимо проверять код и запускать тесты.
- Общая ветка разработки — `develop`.
